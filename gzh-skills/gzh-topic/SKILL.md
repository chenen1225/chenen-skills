# 公众号选题（gzh-topic）

把"模糊的兴趣 / 一堆素材"收敛成一个**能写、想读、有陈恩味**的选题。陈恩定位：杂家型实践者（高企认定 / AI 应用 / 科创），文章以自身经历为素材。

## 触发场景

- "帮我想个选题""这篇写什么""给我个角度""开个选题会"
- 用户甩来一段经历、一个工具、一个痛点，要变成文章

## 选题三源

1. **读者痛点**：高企申报 / AI 落地 / 副业创业里，大家卡在哪（如"研发费用归集搞不清"）
2. **个人实践**：陈恩自己踩过的坑、做出来的东西（如"高企认定智能助手"从 0 到 1）
3. **热点 / 冲突**：行业新规、争议、反常识数据

## 标准流程

```
1. 收口：用户给的是素材还是方向？缺哪头问哪头（不要一次抛太多问题）
2. 发散 3 个角度（不同读者、不同价值点）
3. 用三问筛一个：
   - 陈恩有真实故事 / 数据支撑吗？（没就换）
   - 读者看完能马上用吗？（给落地路径）
   - 跟别的号写得不一样吗？（具象词代官话）
4. 产出：
   - 标题候选 ×3（口语、带数字或冲突）
   - 导读口径（一句话价值）
   - 分章大纲（01/02/03，每章一句结论）
5. 交 gzh-write 起草
```

## 标题公式（参考）

- 数字 + 反差：「67 分起步，我用 183 天把高企通过率拉到……」
- 痛点 + 解法：「研发费用总归集错？一表理清 8 大类」
- 第一人称经历：「我辞掉咨询去写代码，做了个高企助手」

## 与 gzh 技能衔接

- 上游：用户素材 / 热点
- 下游：gzh-write（按大纲撰写）→ gzh-image → gzh-html → gzh-draft
